# Запуск в Windows

1. Дважды щёлкните `Запустить_симулятор.bat` в корне проекта. Страница откроется в браузере; команды вводить не нужно.
2. Оставьте окно launcher открытым. Чтобы остановить запущенный им симулятор, нажмите **Ctrl+C в этом окне**. Если Windows затем спросит `Terminate batch job (Y/N)?`, введите `Y` и нажмите Enter. Другие серверы не останавливаются.
3. Для ярлыка дважды щёлкните `Создать_ярлык.bat`. На рабочем столе появится «Запустить_симулятор». Не переносите отдельный BAT из проекта. После переноса всей папки создайте ярлык заново.

Повторный запуск открывает уже работающий экземпляр именно этой папки: проверяются команда Python, путь `app.py`, рабочая папка, владелец порта и готовность Streamlit. Любой занятый порт не считается симулятором. Если 8501 занят чужим сервером, выбирается свободный локальный порт и его адрес показывается в окне.

При ошибке окно остаётся открытым. Прочитайте причину над строкой «Программа не запущена». Если найден процесс этого проекта, но страница ещё не готова, подождите и повторите запуск — второй экземпляр не создаётся.

Используется фактическое рабочее окружение проекта: `.venv\Scripts\python.exe`, Python 3.12.14, Streamlit 1.58.0. Launcher рассчитан на это 64-битное Windows-окружение. Он не устанавливает зависимости и не изменяет ExecutionPolicy, настройки защиты Windows, расчёты, данные или модели.

Если страница уже была запущена вручную или другим окном, повторное открытие launcher не переносит управление сервером: для остановки используйте исходное окно запуска. Отказ Windows в чтении сведений процесса или нестандартный способ запуска могут помешать достоверному распознаванию; launcher не завершает чужие процессы.

## После обновления Python-файлов

Если после замены кода возникает ошибка импорта, а в новом процессе функция импортируется успешно, остановите симулятор в исходном окне и запустите BAT заново. Работающий Python может хранить старую версию импортированного модуля в памяти. Обновление страницы и кнопка очистки кеша интерфейса не гарантируют повторный импорт таких модулей.

Повторный BAT намеренно открывает существующий сервер, а не перезапускает его: так сохраняется текущая рабочая сессия. После изменения исходников нужен явный перезапуск. При этом временные значения Session State сбрасываются; сохранённые файлы данных и моделей не меняются.

## Проверка 10.10.2026

Проверено в текущей Windows, не только статическим просмотром:

- BAT запускается из другой рабочей папки, включая тестовый путь с пробелами и кириллицей.
- Новый тестовый Streamlit-сервер запускается; повторный BAT открывает тот же PID, не создавая второй сервер.
- Занятый посторонним тестовым HTTP-сервером порт пропускается; этот сервер продолжает работать после Ctrl+C симулятора.
- Ctrl+C в собственной Windows-консоли останавливает тестовый симулятор. Временные тестовые процессы убраны.
- Unicode-ярлык создан в тестовой папке, повторно прочитан через IShellLinkW; путь и рабочая папка совпадают. Ярлык на реальном рабочем столе автоматически не создавался: для этого есть `Создать_ярлык.bat`.
- Отсутствие `.venv` даёт понятную ошибку и `pause`, а не автоматическую установку.
- Настоящий BAT повторно открыл работающий симулятор на 8501: PID 34240 остался прежним. Запрос открытия браузера выполнен без сообщения об отказе; отображение вкладки визуально не проверялось.
- 95 unit-тестов проекта прошли; синтаксис новых Python-файлов проверен `compileall`. В первом запуске suite три проверки столкнулись с ограничением доступа к системной временной папке; повтор с временной папкой внутри проекта прошёл. Критерии тестов не менялись.
- Контрольные хеши существующих корневых Python/CSV/JSON/joblib-файлов до и после сквозной проверки совпали. Приложение, расчётные модули и производственные данные в этом задании не редактировались.

Код проверок: `tests/test_windows_launcher.py` и `scripts/verify_windows_launcher.py`. Изолированные материалы оставлены в `.test_tmp/launcher_*`; внутри есть ссылка на `.venv`, поэтому их не следует удалять командой, рекурсивно обходящей ссылки.
