# Публікація та оновлення GitHub

Робоча папка симулятора залишається основною. Публічний Git відстежує тільки переглянуті файли з явного списку в `.gitignore`. Додавання нового файла до цього списку потребує перевірки. Не використовуйте `git add -f` для даних, результатів або моделей.

## Перша публікація

Після погодження файлів та за умови, що адреса репозиторію вільна, увійдіть через браузер:

```powershell
gh auth login --hostname github.com --git-protocol https --web
gh auth status
gh auth setup-git
```

Не вставляйте пароль або токен у чат чи у файл проєкту. Створення репозиторію не потребує додавання README або ліцензії на сайті. У корені робочої папки:

```powershell
git init -b main
git add -A
git diff --cached --name-status
git diff --cached
git commit -m "Publish adsorption breakthrough simulator"
gh repo create Helmetton/adsorption-breakthrough-simulator --public --source . --remote origin
git remote -v
git push -u origin main
```

`git init` пропустіть, якщо Git уже налаштований. Якщо Git просить вказати автора, задайте ім’я та адресу лише для цього репозиторію. Для приватності можна використати точну noreply-адресу з налаштувань GitHub. Якщо цільовий репозиторій уже існує, зупиніться та звірте його історію перед налаштуванням `origin`; не використовуйте force push.

## Наступне оновлення

1. Перегляньте зміни: `git status --short` та `git diff`.
2. Запустіть доречні перевірки. Для публічного набору: `python -m unittest discover -s tests -p test_public_demo.py` у робочому віртуальному середовищі.
3. Додайте лише погоджені файли через `git add <шлях>`; перегляньте `git diff --cached`.
4. Виконайте `git commit -m "Опис зміни"`, потім `git push`. Для перегляду історії використовуйте `git log --oneline`; щоб скасувати вже опубліковану зміну новим комітом, використовуйте `git revert`.

Запит для Codex: **«Перевір зміни, зроби commit та онови GitHub»**. Codex спочатку переглядає diff, запускає доступні тести, показує підсумок і запитує підтвердження commit/push. Автоматичного push після збереження файла немає.

## Live Demo

Для відкритого доступу використовуйте **лише `cloud_app.py`**. Це окремий інтерфейс на чинному механістичному ядрі: синтетичний сценарій, обмежені параметри й розмір розрахунку, графік і CSV. Вхідні файли, завантаження моделей від відвідувачів та встановлення пакетів недоступні. Калібрування лабораторних даних і навчання ML залишаються в `app.py` для локального запуску. Не відкривайте локальний сервер через публічний тунель.

Під’єднайте GitHub у [Streamlit Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy) та виберіть `Helmetton/adsorption-breakthrough-simulator`, гілку `main`, точку входу `cloud_app.py` і Python 3.12. Залежності беруться з `requirements.txt`. Запускати `demo_data.py` або додавати секрети не потрібно. Після розгортання відкрийте публічну адресу, перевірте графік, змініть витрату та запустіть симуляцію.
